# @zodapp/eslint-plugin-i18n-messages

`@zodapp/i18n-messages` の辞書のキーの直後に、基準の言語（既定は日本語）の文言をコメントで書かせる ESLint のプラグインです。コードを読むときに辞書を開かずに済み、コメントはビルドで消えるのでバンドルの大きさにも影響しません。

```ts
msg("zodFormWidget.import.title" /* i18n: データインポート */);
msgKey("myapp.nameTooShort" /* i18n: ${length}文字以上で入力 */, { length: 3 });
const pair = ["zod.required" /* i18n: 必ず入力してください。 */, {}];
```

## インストール

```bash
pnpm add -D @zodapp/eslint-plugin-i18n-messages
```

## 設定

```js
// eslint.config.mjs
import i18nMessages from "@zodapp/eslint-plugin-i18n-messages";

export default [
  {
    plugins: { "@zodapp/i18n-messages": i18nMessages },
    rules: {
      "@zodapp/i18n-messages/comment": [
        "warn",
        {
          referenceLocale: "ja",
          dictionaries: {
            "myapp.": "src/messages/ja.ts",
          },
        },
      ],
    },
  },
];
```

- `dictionaries`：キーのプレフィックスと、基準の言語の辞書のファイル。相対パスは ESLint の cwd から解決します。プレフィックスは `myapp.`・`myapp.admin.` のように、ドットで終わる識別子（`^([A-Za-z][A-Za-z0-9]*\.)+$`）で書きます。形が違うと、ルールの起動時に設定の誤りとして例外を投げます。プレフィックスが重なるときは、長い方を使います。
- `referenceLocale`：辞書のファイルの中で、この名前の変数（`export const ja = { … }`）を辞書にします。無ければ最初に見つかったオブジェクトリテラル（`defineMessages({ … })` など）を使います（既定 `"ja"`）。

## キーの見つけ方

関数の名前は見ません。次の形の文字列を、どこに書いてあってもキーとして確かめます。キーを受け取って渡す関数の引数・タプル・配列・オブジェクトの値・JSX の属性も対象です。

- 文字列リテラルか、`${}` を含まないテンプレートリテラル
- 値の全体が「プレフィックス＋ `[A-Za-z0-9_]+(\.[A-Za-z0-9_]+)*`」で、後ろに `msgKey` の書式の `?params` が付いてもよい

`"myapp.dev/docs"`（スラッシュを含む）、`"myapp.title "`（空白を含む）、`"myapp."`（残りが無い）はキーとみなしません。

次の場所の文字列は見ません。

- オブジェクトのキー（辞書の `"myapp.title": …` など）
- import・export の `from "…"`
- 型の位置（`type K = "myapp.title"`）
- タグ付きテンプレート

`` `myapp.${code}` `` のように組み立てたキーは確かめられません。

## ルール `comment`

ルールが扱うのは、**目印 `i18n:` の付いたブロックコメント** だけです。目印の無いコメントと行コメントは、読みも消しもしません。

| 状態 | 報告 | `--fix` |
| --- | --- | --- |
| キーの後ろに目印付きのコメントが無い | `missing` | キーのすぐ後ろ（ほかのコメントより前）に書き込む |
| 辞書と食い違う | `mismatch` | 目印付きのコメントだけを書き直す |
| 目印付きのコメントが 2 つ以上ある・改行を含む | `malformed` | 1 つにまとめる |
| 知らないエスケープがある | `invalidEscape` | しない |
| 辞書に無いキー | `unknownKey` | しない |
| 目印付きのコメントが、キーのすぐ後ろ以外にある | `orphan` | 消す |

「キーのすぐ後ろ」は、キーの文字列から次のトークン（カンマ・閉じ括弧など）までの間です。キーを消したり、キーでない文字列に書き換えたりしたあとに残った目印付きのコメントは `orphan` になります。

JSX の属性の値（`label="myapp.title"`）には後ろにコメントを置けないので、`--fix` は `label={"myapp.title" /* i18n: タイトル */}` に書き換えます。

書き込む文言は、辞書の項目のソースから作ります（辞書は実行しません）。

- 文字列リテラル → その値
- 本体がテンプレートリテラル（か文字列リテラル）だけの関数 → テンプレートの中身（`${count} 件を取り込み予定`）
- それ以外 → 本体のソース（改行とインデントは空白 1 つにまとめる）
- 空の文字列 → `/* i18n: */`

コメントの中では `\\`（`\`）、`\n`（改行）、`*\/`（`*/`）だけをエスケープします。突き合わせでは、エスケープを戻し、空白の連続を 1 つにまとめ、前後を取り除いてから比べます。

辞書は、静的なオブジェクトリテラルで書いてください。スプレッドや計算したキーは追えません。

## 性能

文字列リテラルとテンプレートリテラルを 1 回ずつ見るだけで、型情報は使いません。辞書は構文木を作ってキャッシュし、ファイルの mtime が変わったときだけ読み直します。
