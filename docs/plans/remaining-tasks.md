## 3. 決めること（推奨つき）

### 3-1. 表の並べ替えの基準

今は生の値で並ぶ。拠点（select）は ID の順、担当（externalKey）は ID の順、金額（dynamic）は円とセントを同じ数として比べる。小計（computed）は並べ替えできない。

推奨：列の種類ごとに決める。

| 列 | 並べ方 |
|---|---|
| 数・日付・時刻・文字 | 値で並べる（今のまま） |
| select（enum） | 選択肢を定義した順 |
| externalKey | 表示名（ラベル） |
| computed | 計算した値 |
| dynamic（行ごとに意味が変わる列） | 並べ替えできないようにする |

### 3-2. 開いただけで値を書き換えるもの

unlisted の clear と、`z.preprocess` で包んだ union（開くと `type: "email"` が補われる）は、開いただけで値を書き換える。precision の欄は書き換えない。

推奨：書き換えてよい（clear と同じく、仕様として README に書く）。ただし isDirty は、開いたときの書き換えでは true にしない。

- isDirty を true にしない作り方（開いたときの書き換えが終わった値を、比べる元の値にする）は、dynamic の選択肢が遅れて届いて clear する場合もあるので、実装の前に作り方を調べて、このファイルに書き足してから進める
- 調べて無理があれば、「開いたときの書き換えでも isDirty は true になる」を仕様にして README に書く

### 3-3. clear・prune で消えた欄に、すぐ「必ず入力してください」が出る

推奨：触っていない欄には、送信を押すまで必須のエラーを出さない（ほかの必須の欄と同じ扱い）。

### 3-4. 送信が止まった理由が画面に出ない

読み込み中や取得の失敗で送信が止まっても、画面には何も出ない（console にだけ出る）。

推奨：送信のボタンの近くに、止まった理由を出す（「読み込み中の欄があります」「取得できなかった欄があります」「入力に誤りがあります」）。

### 3-5. モックの topic 名を間違えても気づけない

今は空の選択肢が届くだけ。

推奨：無い topic は `onError` で失敗にする（「topic "…" がありません」）。欄には error と「再試行」が出る。

### 3-6. `allowUnlisted` と `unlisted` の名前が近い

`allowUnlisted`（選択肢に無い値も正しい値として通す）と `unlisted`（外れた値を消すか残すか）は意味が違うが、名前が近い。両方書くと `allowUnlisted` が勝ち、`unlisted` は効かない。

推奨：名前は変えない。両方を同時に書けないように型でふさぎ、README に違いを書く。

### 3-7. `useRunAsUserEdit` を残すか

unlisted を作り直したので、enum の値は出どころ（利用者の編集か外からか）に関係なく、clear なら消え、keep なら残る。出どころで変わるのは、型が合わない値の prune だけになった。

推奨：残す。効く範囲（型が合わない値の prune だけ）を README に書き、`e2e-dynamic` のボタンで確かめる。

### 3-8. clear は描かれている欄だけに効く

折りたたまれた union の腕など、描かれていない欄の値は残る。

推奨：仕様として README に書く。

### 3-9. main の README に公開リポジトリで使わない語が残っている

`packages/zod-form/README.ja.md` の 85〜88 行。

推奨：その行を消す。別のコミットにして、PR #21 に載せる。

## 4. e2e で確かめること（2 のあとに足すページ）

2 のページに加えて、次のページを作る。期待値は 3 で決めた内容に従う。

### `e2e-external-key`：選択肢の届き方

すでにある e2e（`external-key-filter.spec.ts`・`select-and-external-key.spec.ts`）が確かめている、clear・keep・filter・context・config の key は、そのまま残す。新しいページでは、時機に関わるものを確かめる。

- 選択肢を止めておいたまま、context（部署）を変える・値を選ぶ・送信する。届いたあとの値と、送信が止まること
- 同じ購読のまま、選択肢が 0 件になる・戻る
- 無い topic の欄は失敗になる（3-5）
- 取得の失敗と再試行（2 の失敗の仕組み）
- subscribe で届く dynamic（在庫の上限）：上限が変わると検証も変わり、値は消えない

### `e2e-open-rewrite`：開いただけで書き換えるもの（3-2）

- 開いたとき、clear の欄の外れた値が消え、keep の欄は残る
- preprocess の union は、開くと決めた形に補われる
- precision の欄は書き換えない
- isDirty が 3-2 で決めたとおりになる

### `e2e-union`：union の腕の切り替え

- 腕を切り替えると、前の腕だけにあった値が消え、新しい腕の既定の値が入る
- 元の腕に戻したときの値
- 描かれていない腕の値と clear（3-8）
- 期待値は、実装の前に今のふるまいを画面で確かめ、このファイルに書き足してから進める。仕様と食い違うものが見つかったら、そこで止めて決める

### `e2e-table`：表

- 並べ替え（3-1 で決めた基準）
- dynamic のセル（行の通貨で表示が変わる）
- 選択肢に無い値のセルの表示

### 決めたことの e2e

- 3-3：clear・prune で消えた欄に、触る前は必須のエラーが出ない
- 3-4：送信が止まったとき、理由が出る
