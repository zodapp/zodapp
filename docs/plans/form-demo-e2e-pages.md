# form-demo に、メニューに出さない e2e 用のデモページを足す

## 目的

e2e が失敗したとき、人が同じ URL を開き、同じ手順を手で試して確かめられるようにする。
そのために、カタログ（メニューに出るデモ）とは別に、e2e で確かめたいことを置くデモページを作り、それに対して e2e を書く。

- 部品・レイアウト・デザインは、今のデモページと同じにする。違うのは、メニュー・トップ・一覧に出さないことだけ
- テストの手順は、ページの説明に書く手順と同じにする（`playwright.config.ts` の「手順はページを開いて試す手順と同じにする」と同じ方針）

## 前提

- 3・4 のページは、時刻の打ち込みの修正（B）と、日時の precision・unit の修正（D）のあとの挙動を確かめる。A・B・D が main に入ったあとの main から、新しいブランチで実装する
- 選択肢を届け直すボタン（A）は、公開のデモページ「zf.externalKey」に置いたままにする。この計画では動かさない

## 置き場所と登録

- `apps/form-demo/src/pages/form/schemas/e2e/` に置き、別の登録簿 `e2eSchemas`（`schemas/e2e/index.ts`）を作る。モジュールの形（`formId`・`title`・`description`・`schema`・`defaultValues`・`Component`）は今のデモと同じ
- formId は `e2e-` で始める（例：`e2e-dynamic`）
- 詳細ページ（`/form/detail?formId=…`）は `formSchemas` と `e2eSchemas` の両方から引く。サイドバー（`Layout.tsx`）・一覧（`list.tsx`）・トップは `formSchemas` だけを使うので、e2e のページは出ない
- 「コード」タブも今のデモと同じに出す（`?raw` の import を `e2eCodes` に置く）
- GitHub Pages のビルドにも含める（URL を知っていれば開ける）

## 共通のハーネス

e2e のページは共通の部品（`E2eHarness`）で AutoForm を包み、次を出す。テストが読むためだけでなく、人が読んで分かる表示にする。

- 今の値（showPreview と同じ JSON の書式）
- 欄ごとのエラー（`form.getAllErrors()` の fields と form）
- isDirty
- 送信した値と、送信の回数（送信が止まったときは回数が増えない）
- 必要なページだけ：「外から書き込む」「利用者の編集として書き込む」（`useRunAsUserEdit`）のボタン

それぞれに `data-testid` を付ける。ハーネスは AutoForm の `actionComponents` として描き、form の API を受け取る。

## 遅延とタイミング

- 遅延の既定は、本物に近い値にする（今のモックの 400 ms、帳票の読み込みの 1 秒など）。遅延 0 には決め打ちしない
- タイミングそのものを確かめるケースだけ、ページ上で遅延を選べるようにする（0・1 フレーム後・2 フレーム後・長め）。選んだ遅延は画面に出す
- フレーム単位の遅延が、今のモックの ms の遅延で表せないときは、デモ側の resolver で `requestAnimationFrame` を使って作る。zod-form のモックの API を広げる必要が出たら、そのときに別のコミットにする
- 周期で起きる動きは使わず、ボタンで 1 回ずつ進める
- テストは時間を待たず、画面の状態（読み込み中が消えた、選択肢が出た、エラーが出た）を待つ

## 最初に作るページ

### 1. `e2e-dynamic`：dynamic の読み込み・失敗・再試行・連鎖

ページ：帳票の種類（load で項目を取る）、都道府県 → 市区町村 → 町名の連鎖、取得を失敗させるスイッチ、遅延の選択、外からの書き込みと利用者の編集としての書き込みのボタン

e2e：
- 帳票の種類を変えると、項目が読み込み中になり、新しい項目が出る。取り直すのは帳票の項目だけ（ほかの欄は読み込み中にならない）
- 取り直し中に送信すると、送信は止まる（送信の回数が増えない）
- 失敗させて種類を変えると「再試行」が出る。失敗をやめて再試行すると戻る
- 種類をすばやく行き来すると、最後に選んだ種類の項目だけが残る
- その種類で初めて使う部品が出ても、ほかの dynamic の欄は取り直さない（以前の不具合の再発を防ぐ）
- 都道府県を変えると、市区町村・町名が順に消える。都道府県を消すと、市区町村は「先に都道府県を選んでください」で無効になり、必須エラーは出ない
- 遅延を 0・1 フレーム・2 フレームにして、上の結果が変わらない

### 2. `e2e-time-input`：時刻の打ち込み

ページ：`z.iso.time({ precision: 3 })`・`z.iso.time({ precision: 1 })`・`z.number()` + `millisecondsOfDay` の欄

e2e（キーを一つずつ押す。`pressSequentially`）：
- 空の欄に `10:45:30.123` を打って欄を出ると、表示も値も `10:45:30.123`
- 途中の桁を Backspace で消して打ち直すと、打ったとおりになる
- Enter で値に入る
- 読めない値（`9:30`）で欄を出ると、形のエラーが出て、送信が止まる。前の値が黙って残らない
- 範囲外（`12:60:00`）で欄を出ると、必須ではなく形のエラーが出る

### 3. `e2e-precision`：precision・unit で書かれる形と、開いただけで書き換えないこと

ページ：日時（Z あり・local）と時刻の、precision なし × unit（minute・second・millisecond）と、precision -1・0・3 の欄。初期値は固定の日時（開いた時刻にしない）

e2e：
- 開いただけでは値が変わらない（isDirty が false、値が初期値のまま）
- 各欄を編集すると、決めた形で書かれる（precision なしの日時は unit で決まる。minute でも秒まで `:00` を書く）
- unit が保存値より粗い欄は、編集すると細かい部分が 0 になる

## 対象外（あとで足す）

- 開いたときの書き換え（unlisted の clear・preprocess）と isDirty
- union の腕の切り替え
- 表（並べ替え・dynamic のセル・選択肢に無い値）

## e2e の実行まわり

- `playwright.config.ts` のポートを環境変数（例：`E2E_PORT`、既定 3000）で変えられるようにする。別の作業コピーの dev サーバーを相手にテストしてしまうのを防ぐ
- `all-pages.spec.ts` に、`e2eSchemas` のページもすべて開け、例外が起きないことを足す（サイドバーのリンクからはたどれないため、formId の一覧をテストから読む）
- タイミングを確かめるケースは CI で揺れやすいので、画面の状態を待ち、待ち時間に余裕を持たせる。それでも揺れるケースは単体テストに回す
