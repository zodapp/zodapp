# form-demo の e2e をそろえる

## 目的

e2e が失敗したとき、人が同じ URL を開き、同じ手順を手で試して確かめられるようにする。そのために、e2e で確かめたいことをデモページに置き、それに対して e2e を書く。あわせて、スモーク e2e で見つかったライブラリの不具合を直す。

## 決めたこと

- **e2e のケースは、重なるデモページ（メニューに出るデモ）に置く。** 欄が足りなければ、そのデモに欄を足す。テストの手順は、ページの説明に書く手順と同じにする。spec は 1 つのデモページに 1 つにする
- **フォームの外から動きを起こす操作は、「動きを試す」の枠（`TryBehavior`）にまとめる。** 遅延の分け方の選択、止めておいた取得の「届ける」「失敗させる」、選択肢の届け直しなどで、フォームの欄と見分けられるようにする。人が開いたときの既定は、デモの見やすいふるまい（ms の遅延など）のままにし、テストは分け方を選んでから進める
- **e2e 用のページ（メニューに出ない）は、デモに向かないものだけに使う。** わざと選択肢に無い初期値や古い形の初期値を持つ `e2e-open-rewrite` だけ
- **ライブラリの直しは、項目ごとに単体テストと README を合わせて直す。** 主なもの：
  - clear・prune で値を消しても、その欄を「触った」「変えた」にしない（開いただけで `isDirty` にならない）
  - 送信が止まった理由を、AutoForm のボタンの行の近くに出す
  - モックの無い topic を購読したら失敗にする（名前の間違いに気づけるように）
  - `allowUnlisted` と `unlisted` を同時に書けないようにする
  - 表の並べ替えの基準を、列の種類ごとに決める（externalKey は表示名ではなく保存している値で並べる。dynamic は並べ替えない）

それぞれの今の仕様は、zod-form と zod-form-widget の README にあります。
