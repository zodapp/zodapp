## Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project aims to follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## Unreleased

- Initial public release preparation
- zod-dynamodb: add `subscribeOnServer`, which lets server code subscribe to a `live` query. Server-only queries (without `authorize`) can now be `live`; the Realtime Gateway does not expose them
- taskmanager: distribute member changes as revocations, so every instance rebuilds the auth context of the affected Realtime connections even with multiple Realtime Gateways
- zod-transform: fix intersection so that the right side's pass-through values no longer overwrite the left side's transformed values. A key removed by `$remove` on one side is now kept removed when the other side only passes it through
- zod-form-widget: wrap AutoForm in a `<form>` element so that pressing Enter in a field submits it. Enter presses the first `type: "submit"` action (including the submit button from the `onSubmit` prop), which is now rendered as an HTML `type="submit"` button. To make a `custom` action the Enter target, give its button `type="submit"`. **Behavior change**: in an AutoForm with a submit button, pressing Enter in a text field now submits the form (Enter in a textarea still inserts a newline)
- zod-form-widget: add `actionsPosition` (`"top"` | `"bottom"`, default `"top"`) to AutoForm, so the button row can be placed below the fields
- taskmanager, survey: on the sign-in, sign-up, confirmation code and password reset screens, place the button below the fields at full width
- zod-form-mantine: enums with `uiType: "badge"` now show the selected value as a badge too, not only the options. While the dropdown is open the field becomes a text input (the selected label is shown as the placeholder) and filters the options; the typed text no longer gets appended to the selected label. The read-only display is also a badge. Built on the new `BadgeSelect` in `@zodapp/zod-form-mantine-lite/utils`
- zod-form-mantine: `uiType: "multipleEnumBadge"` shows the selected values as badges that can be removed with ×, and its read-only display as badges
- zod-form-mantine: **Breaking**: rename `uiType: "multipleEnumBudge"` to `"multipleEnumBadge"` (the old spelling is no longer recognized)
- zod-form-mantine-lite: badges (enum options, selected value and read-only display, multi-select, and computed badges in tables) now pick their text color from the background. For shaded theme colors (`"blue.6"`) and RGB colors (`#3b82f6`, `rgb()`, `hsl()`), the background is that exact color and the text is the same hue made darker (OKLCH lightness minus 0.45), or white on dark backgrounds and where white has higher contrast. Unshaded theme colors (`"blue"`) keep Mantine's `light` variant. Adds `ColorBadge` and `computeBadgeColors` to `@zodapp/zod-form-mantine-lite/utils`
- zod-form-mantine: fixed unions without a discriminator (`zf.union`) clearing the selector and hiding the arm's fields after picking an object arm. The selected arm is now remembered and stays shown while the value does not yet pass its schema. When the value changes from outside and passes only another arm, the selector follows it. When the initial value passes no arm, the object arm whose literal fields (e.g. `type: "phone"`) match is shown if exactly one matches. Switching arms no longer validates, as with discriminatedUnion
- zod-form-react: **Breaking**: `ZodFormProps.required?: boolean` is inverted to `optional?: boolean` (`true` inside an outer `.optional()` or `.default()`; omitted means required). Adds `nullable?: boolean`; zod-form-mantine-lite's `NullableComponent` now passes `nullable` instead of `optional`. `useDynamicSchema`'s `{ required }` option is now `{ optional }`. In custom components, read `required !== false` as `!(optional || nullable)` and `required={false}` as `optional={true}`
- zod-form-react: `FormRuntime.validate` now keeps zod issues whole (only the outermost path is prefixed; the per-arm `errors` of `invalid_union` are left as they are). The error passed to components (`wrapComponent`, array fields) is now the first error that is not `invalid_union`
- zod-form-mantine: fixed errors of unions without a discriminator (`zf.union`). An error for a value that matches no arm's type (e.g. an empty number arm) is now shown on the selected arm's field (in AutoForm nothing was shown, and with a schema passed directly to `useZodForm` it re-rendered endlessly). The arm's errors are added to the errorMap `onDynamic` slot of the same field while `invalid_union` stays. This also works when unions are stacked on the same field and for a union in a child field of an object arm. When no arm is selected and validation fails (an empty required union, or a value matching no arm), the arm selector shows 「選択してください」
- zod-form-mantine: in optional and nullable `zf.union`, × clears the arm and empties the value, and picking an arm whose default is empty writes the empty value. The empty value is `undefined` when optional, `null` when only nullable (`undefined` when both)
- zod-form-mantine: fixed the first submit right after switching `zf.union` arms stopping without validation
- zod-form-mantine: fixed a type error in a child field of a `zf.union` object arm (e.g. an empty number) staying shown after it was fixed without leaving the field. A discriminatedUnion with no arm selected (required and empty) now also shows 「選択してください」 on the arm selector. Fixed nested unions writing errors to non-existent fields (such as `value.value`)
- zod-form-mantine: fixed a discriminatedUnion whose saved value has no discriminator showing no error while blocking submit (the error was on a field that is not rendered). The arm selector now shows 「選択してください」
- zod-form-react, zod-form-mantine: **Breaking**: clearing a field that is only nullable (including multi-selects) now writes `null` instead of `undefined`, so it no longer shows a required error and can be submitted empty. Optional fields (including optional and nullable) still write `undefined`. `emptyValueOf` is exported from zod-form-react. `useDynamicSchema` gains a `{ nullable }` option
- zod-form-mantine-lite: reactive components now replace an empty value (`""` or `null`) passed to `onBlur` and `onConfirm` with the field's empty value (`undefined` when optional, `null` when only nullable). `useConfirmableState` gains an `emptyValue` option
- zod-form-mantine-lite: the reactive date field now passes the stored format (Date, number or string) to `onBlur` and `onConfirm` instead of the picker's string. `useConfirmableState` gains a `toValue` option
- zod-form-mantine: the bigint field now accepts only digits and a leading `-`
- zod-form: `getDefaultValue` now gives `undefined` instead of `null` for fields that are both optional and nullable (`.optional().nullable()`), matching the value written when the field is cleared
- zod-form: `getDefaultValue` no longer lists object keys whose value would be `undefined` (`{}` instead of `{ x: undefined }`). Keys of required children that accept `undefined` (such as `z.unknown()`) are kept
- zod-form: `getDefaultValue(schema, value)` walks the schema with the current value and fills only the missing parts with defaults, including array elements, record values and union arms. `adaptValueToSchema` now fills this way
- zod-form-react, zod-form-widget: when a `zf.dynamic` schema is first resolved, missing parts of the value are filled with that schema's defaults (nothing is removed). The fill is registered in `FormRuntime`, and AutoForm also applies it to its defaultValues through `useDefaultValuesWithFills`, so opening a form does not make it look changed and `reset` keeps the filled values
